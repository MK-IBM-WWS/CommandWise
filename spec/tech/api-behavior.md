# Поведение API и поток

JWT действует 24 часа. Браузер получает HttpOnly-cookie `cw_session`. Для CLI заголовок `X-Auth-Mode: bearer` при входе или регистрации возвращает поле `token` вместо cookie. Выход отзывает сессию. Чаты доступны только владельцу, управление корпусом доступно роли admin. Регистрация выдаёт только роль user.

Дистрибутив выбирается из corpus API и фиксируется на весь чат. Поле release в старых клиентских запросах принимается для совместимости и игнорируется. Пользователь хранит до 10 чатов и может удалять завершённые чаты. POST вопроса принимает UUID `client_request_id`. Дубликат возвращает 409 REQUEST_EXISTS с ID существующего ответа. На чат допускается одно ожидающее или активное задание. Состояния ответа: queued, generating, complete, cancelled, error.

POST с `stream:false` возвращает 202 и сообщение со статусом queued. С `stream:true` ответ 200 открывает SSE. События идут в порядке status → sources → token → done либо error. Во время ожидания поток передаёт keepalive. Событие token содержит `delta`, done содержит `message_id` и `finish_reason`, error содержит `code` и `message`. GET истории всегда показывает состояние и сохранённую часть ответа. Явный POST cancel отменяет ожидание или генерацию. Закрытие потока оставляет задание в очереди или на исполнении, чтобы переключение между чатами и обновление страницы сохраняли работу.

Лимиты: 10 чатов на аккаунт, 2 исполнения глобально, 1 исполнение и до 10 ожидающих заданий на аккаунт. Допускается до 100 ожидающих заданий глобально при нескольких аккаунтах. Готовые к запуску задачи выбираются в порядке поступления. При перезапуске backend ожидающие задания восстанавливаются, прерванные получают error с сохранением опубликованного текста.

Администратор загружает Markdown UTF-8 до 512 КиБ и указывает проверенную систему, версию пакета, дату и HTTP(S)-ссылку. Публикация индекса происходит после успешного пересчёта. Snapshot прежнего ответа продолжает ссылаться на тот фрагмент, который использовался при генерации.
