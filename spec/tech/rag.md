# Спецификация BM25 и RAG

## Обязательный метод и роли

Первая реализация использует BM25 по требованию курса. Search на Python отвечает за retrieval; Go выполняет сборку prompt и вызов модели. GPU нужен LLM, не BM25. Индекс, эмбеддинги и модель генерации не смешиваются в одно неясное понятие.

## Источники и корпус

Один Markdown-документ на команду: назначение, синтаксис, параметры, задачи, примеры, подтверждённые общие части и особенности систем. Источники — действительные man/upstream-руководства; перевод сохраняет команды/flags/пути и проверяется человеком.

Предварительный охват: Debian 13, Ubuntu 24.04, Fedora 44, Arch с датой снимка. Эти варианты не объявляются в manifest без реальной проверки. Общий GNU-раздел может быть один; не требуется искусственно дублировать его для четырёх систем. Отличия определяются версией реализации/пакета и настройками.

## Metadata

Manifest: corpus_version, collected_at, supported_targets, документы, hashes, источники. Chunk: chunk_id, document_id, command, title, section, text, source_url, distribution, release, package_version, collected_at, applies_to.

Общий chunk имеет distribution=common, release='*', но применяется только к проверенным парам applies_to. Архив Arch — snapshot-YYYY-MM-DD с реальной датой. chunk_id — стабильный content/metadata hash; изменение текста меняет id.

## Chunking и tokenization

Markdown делится по смысловым разделам; ориентир 800–2000 символов, максимум примерно 3000, уточняется benchmark. Не разрывать code blocks, отдельную команду или смешивать несовместимые target.

Русские слова нормализуются и стеммятся NLTK Snowball; флаги, пути, числа и имена команд выделяются отдельно и сохраняются, включая case -r/-R. Один tokenizer применяется к query и corpus. Текст для показа не заменяется стеммами. Синонимы вводятся прозрачно и проверяются на dev.

## Индекс и поиск

rank-bm25 BM25Okapi, начально k1=1.5, b=0.75. Индексатор готовит chunks/tokens и index metadata отдельно. При старте runtime один раз восстанавливает статистику BM25; не парсит/переводит corpus на каждый вопрос. Runtime package read-only; новая версия публикуется атомарно после валидации.

BM25 вычисляет scores; совместимые target candidates отбираются **до top-k**. Общие части учитывают applies_to. Результат deterministic при равных scores. score не вероятность; универсальный порог score>0 не вводится. Отсутствие совместимых документов/содержательных совпадений даёт items=[]; слабая релевантность анализируется на dev-вопросах и полном RAG.

## Генерация

Стартовая модель Qwen2.5-7B-Instruct Q4_K_M в Ollama — кандидат, не объявленное измеренное качество. Prompt: русский ответ, target, номерные sources, точный CLI-синтаксис, документы как данные, отказ при недостатке оснований. Контекст ограничивается без разрыва команд; history не передаётся бесконечно.

Сначала реализуется stream=false, затем SSE. Если context пуст, выдаётся no_context; при отказе search/LLM — сервисная ошибка. Нельзя незаметно переключить production на canned response.

## Проверка

Метрики retrieval и полного RAG — в [testing](testing.md). Обязательно отслеживать source correctness, target compatibility, отказ для неизвестного и вопросы без имени команды. Успешный retrieval не доказывает истинность всего ответа модели.

Сейчас реальный корпус, индекс и benchmark-результаты не предоставлены. Прототип содержит только fixture-тексты для демонстрации UX. Наполнение и измерения — следующий этап.
