# Архитектура CommandWise

Проект разворачивается на Fedora Linux или Debian 13 x86_64 с NVIDIA GPU. Для обеих ОС установщики работают с общей конфигурацией из пяти сервисов Docker Compose.

| Сервис | Реализация | Назначение |
| --- | --- | --- |
| frontend | React, TypeScript, Vite, Nginx | Интерфейс чата и отдельный интерфейс администратора |
| backend | Go, net/http, pgx/v5, goose | JWT, история, очередь, SSE, сборка RAG-запроса |
| search | FastAPI, BM25, multilingual-e5-small ONNX | Поиск по проверенному корпусу, переупорядочивание кандидатов, публикация индекса |
| llm | llama.cpp CUDA, Qwen3-14B Q4_K_M | Два параллельных ответа с общим контекстом 8192 и 4096 токенами на слот |
| postgres | PostgreSQL | Аккаунты, JWT-сессии, чаты, очередь, snapshot источников |

Браузер обращается к Nginx через один origin. Nginx проксирует `/api/v1` в Go. База, Search API и llama-server доступны во внутренней сети Compose. Поиск и эмбедер используют CPU. GPU получает только llama-server.

Go закрывает PostgreSQL-транзакцию до вызова Search или LLM. Планировщик выбирает задания из PostgreSQL с учётом пользователя, держит два рабочих слота и сохраняет частичный текст. Модель отвечает по фрагментам для выбранной системы. При пустой выдаче Go сразу возвращает `no_context`. SSE и история читают сохранённое состояние задания.

Search строит индекс из исходного корпуса и документов, опубликованных администратором. Переупорядочивание использует BM25 как основную составляющую ранга и добавляет семантический ранг E5. Публикуется новая версия корпуса целиком. Старые ответы хранят оригинальные фрагменты в PostgreSQL.

На хосте по умолчанию открыт `127.0.0.1:8080`. Для HTTPS через внешний обратный прокси используются `PUBLIC_ORIGIN` и `COOKIE_SECURE=true`.
