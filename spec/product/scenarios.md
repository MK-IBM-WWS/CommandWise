# Пользовательские сценарии

Каждый сценарий имеет ожидаемое поведение рабочей версии. Возможность прототипа указана отдельно: локальные fixtures моделируют интерфейс, а не настоящий поиск/генерацию.

## S01. Основной сценарий

**Условия:** доступ к приложению, действительный корпус с выбранным target.

1. Нажать «Новый чат».
2. Выбрать Debian и release 13 из доступных вариантов.
3. Ввести: «Как найти обычные файлы больше 100 МиБ?».
4. Отправить; увидеть собственное сообщение и статус ожидания.
5. Получить русский ответ с примером команды и источниками.
6. Открыть фрагмент источника; убедиться в параметрах и применимости.

**Приёмка:** выбранный target виден; команда не обрезана; источники соответствуют ответу; пользователь может копировать команду. Прототип выполняет шаги с заранее заданным, явно помеченным demo-ответом.

## S02. Уточнение

После S01 спросить: «А как исключить каталог?». Рабочая версия учитывает ограниченную историю и формирует понятный поисковый запрос. Прототип показывает один заданный пример уточнения; это не проверка диалогового retrieval.

## S03. Выбор другой системы

Открыть форму нового чата, выбрать Fedora и доступный release. Старый чат сохраняет свой target. Рабочая система не переносит неподтверждённые особенности Fedora в Debian-ответ. Прототип показывает выбор и разделение истории, не заявляя достоверное corpus-покрытие.

## S04. Недостаточно информации

Задать вопрос за пределами собранной документации. Рабочая версия объясняет отсутствие подтверждённого ответа для target; `finish_reason=no_context`. Прототип моделирует это состояние для вопроса, не соответствующего demo-шаблонам.

## S05. Отмена

Отправить вопрос, во время появления текста нажать «Остановить». Частичный текст остаётся; статус — cancelled. Следующее сообщение можно отправить. В прототипе отменяется локальный таймер; в рабочей версии отмена проходит до LLM и освобождает слот GPU.

## S06. История

Создать два чата, переключиться между ними, обновить страницу. Рабочая версия получает историю с backend по cookie-сессии; другой браузер не видит чужие чаты. Прототип использует localStorage: он проверяет только UX истории, а не серверную изоляцию.

## S07. Ошибка модели/сети

Рабочая версия отображает понятную ошибку, сохраняет частичный ответ при обрыве и допускает последующий запрос. В прототипе кнопка «Ошибка» моделирует отказ; внешней модели нет.

## S08. Сервер занят

При заполненной очереди рабочая версия возвращает 429, UI предлагает попробовать позже без бесконечного автоповтора. В прототипе показ этого состояния не обязателен; проверить его при реализации API и интеграции.

## S09. Ограничения и доступ

Пустой вопрос не отправляется. Вопрос слишком большой — понятная ошибка. Неподдерживаемый target нельзя выбрать через обычный UI. Прямой запрос к чужому chat_id не раскрывает историю. Прототип проверяет пустой ввод и лимит; серверная авторизация относится к следующему этапу.
