# План и контрольные точки

Точные даты сообщаются преподавателем; календарные дедлайны в этом плане не выдумываются. Статусы относятся к комплекту, а не к неизвестному состоянию удалённого репозитория.

| Задача | Ведущий | Результат | Проверка | Статус |
| --- | --- | --- | --- | --- |
| CP1-01. Продукт и сценарии | Frontend | product/scenarios/interface | Review командой, основной сценарий | Документы подготовлены |
| CP1-02. Архитектура, данные, Go API | Борис | architecture/data-model/api | Review потребителей и контрактов | Спецификации подготовлены |
| CP1-03. BM25, corpus, benchmark design | RAG | rag/testing/search-api | Review gold/target правил | Спецификации подготовлены |
| CP1-04. Интерфейс-прототип | Frontend | автономный prototype | Браузерный показ | Подготовлен в комплекте |
| CP1-05. GitHub workflow и Git-история | Борис + команда | PR, commits, check, tag | Настоящий remote run и Git log | Выполнить в вашем репозитории |
| CP1-06. Review и защита | Все | checklist, demo | Каждый запускает и объясняет | Выполнить командой |
| CP2-01. Реальный corpus 3–5 команд | RAG | sources, chunks, index | validation + retrieval | Следующий этап |
| CP2-02. Go storage/mock API | Борис | API + DB | tests без GPU | Следующий этап |
| CP2-03. React клиент | Frontend | реальные screens/API/SSE | typecheck/build/e2e | Следующий этап |
| CP2-04. LLM и связка RAG | Борис + RAG | real answer/sources | fixed dev subset | После поиска и API |
| CP2-05. Benchmark и расширение | RAG + все | corpus 15–20 команд, metrics | dev/holdout report | После baseline |
| CP3-01. Compose/доставка/restore | Борис | воспроизводимый запуск | smoke/backup restore | Финальный этап |
| CP3-02. Документы и выступление | Все | code/docs/results совпадают | демонстрация и вопросы | Финальный этап |

Backend сначала даёт согласованный mock-контракт; frontend не ждёт модель; RAG работает без GPU. Интеграция проходит по пути одного вопроса, затем подключаются поток, история и отказоустойчивость.

Issues создаются по этим IDs, но сами Issues пока не созданы данным архивом. Разделить большую задачу на PR по конкретному результату. Оценки трудоёмкости команда уточняет после первого baseline.
