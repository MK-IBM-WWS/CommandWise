# Команда и зоны ответственности

Команда состоит из трёх участников. Имена/логины frontend и RAG не были предоставлены при подготовке комплекта; ниже они обозначены по ролям, без вымышленных ФИО.

| Участник | Роль курса | Работа | Результат к точке 1 |
| --- | --- | --- | --- |
| Борис; GitHub-логин вписать командой | Интеграция / backend и DevOps | Go API, модель данных, соединение поиска и LLM, сеть, контейнеры, CI/CD | Архитектура, API, правила репозитория, план интеграции |
| Frontend-участник; имя и логин вписать командой | Продукт и интерфейс | Задача, пользователь, сценарии, UI, React-клиент, состояния/источники | Продуктовые документы и демонстрация прототипа |
| RAG-участник; имя и логин вписать командой | BM25 и RAG | Корпус, перевод, metadata, индекс, поиск, benchmark | RAG-спецификация, формат корпуса и план проверки |

Настоящий URL репозитория: вписать после выбора GitHub owner и имени проекта.

## Общая ответственность

Каждый понимает путь вопроса от интерфейса до источника и ответа, может запустить демонстрационный прототип и объяснить свой компонент. API и переходы между сервисами согласуются до независимой разработки. Prompt проверяют backend и RAG; реальные вопросы для benchmark предлагают все участники. PR проверяет не автор изменения.

## Рабочие границы

- `frontend/`, `prototype/`, `spec/product/`: frontend ведёт интерфейс; прототип из комплекта — первоначальный материал, который команда принимает или правит.
- `backend/`, `infra/`, `.github/workflows/`, architecture/API/data-model: Борис.
- `search/`, `corpus/`, `benchmark/`, rag/search-api: RAG.
- `README.md`, `AGENTS.md`, CHANGE_HISTORY, общий план: согласованные общие правки.

## Порядок совместной работы

1. Совместно принять product, scenarios, API и схему сервисов.
2. Сделать отдельные задачи с результатом и способом проверки; использовать GitHub Issues.
3. Работать независимо с согласованными mocks, небольшими PR и регулярной интеграцией.
4. На точке 1 показать материалы и воспроизводимый прототип; не выдавать фиктивный ответ за работу RAG.
5. На следующем этапе связать BM25/Go/LLM, затем React и проверить benchmark.
