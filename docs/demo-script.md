# Сценарий показа первой точки

План на 5–7 минут, адаптируется под регламент преподавателя. Источник программы — слайд 12; продолжительность — рекомендация команды.

1. Frontend (около минуты): тема, пользователь и задача. «Пользователь хочет найти команду по задаче и проверить ответ по источнику. Выбор системы учитывается в будущем поиске».
2. Frontend (1–2 минуты): открыть prototype, указать видимый banner mocks, создать Debian 13 чат, отправить предложенный вопрос, открыть источник. Показать другое состояние/отмену и историю. «Сейчас это интерфейс-прототип, BM25 и модель подключатся следующим этапом».
3. Борис (1–2 минуты): architecture diagram, Go API и пять сервисов, сервер/V100/Tailscale, main+PR. Показать настоящий GitHub log/PR после загрузки. Не утверждать, что runner уже установлен.
4. RAG (1–2 минуты): один документ на команду, chunks, версии и target-фильтр; русский tokenizer сохраняет flags. Показать методику benchmark и отсутствие выдуманных результатов.
5. Все: team/plan/checkpoint checklist. Каждый может объяснить общий путь запроса и запуск.

## Подготовка

Запустить по README; протестировать браузер до занятия. Если сервер/VPN ещё не настроены, показывать prototype локально — это удовлетворяет текущей задаче. Сохранить screenshots/запись как резерв, не выдавая их за живую модель. Закрытый репозиторий открыть через согласованный доступ или собственный экран.
