# Benchmark контрольной точки НИРС

`corpus.jsonl` содержит 30 проверенных для Debian 13 фрагментов с ID D01–D30. Один фрагмент считается одним документом индекса. На каждую тему пришлось по шесть фрагментов и два обычных вопроса: права доступа, поиск файлов, поиск текста, просмотр каталогов и архивы. Фрагменты зафиксированы с исходным текстом, ссылкой и `chunk_id` приложения.

В `questions.jsonl` сохранены вопросы Q01–Q15, эталоны и релевантные ID. У Q01–Q10 по три или четыре релевантных документа. Q11–Q13 относятся к известной команде, но спрашивают о функции, которой нет в выбранной документации. Q14–Q15 проверяют запросы вне предметной области. Старые dev-наборы можно использовать для настройки отдельно.

Архивный контрольный набор сохраняет исходные 30 фрагментов Debian 13. Он используется для сравнимости прогона. Встроенный корпус приложения расширен до 50 команд для трёх дистрибутивов.

## Результаты

Полная выдача, фактические ответы, времена и оценки по каждому вопросу находятся в [checkpoint.json](results/checkpoint.json). Ручная сверка сохранена в [review.jsonl](results/review.jsonl).

| Вариант | Recall@5 | MRR@5 | Accuracy | Correct Rejection Rate |
| --- | ---: | ---: | ---: | ---: |
| Собственный BM25 | 80,0% | 0,7583 | — | — |
| Собственный BM25 + E5 | 83,3% | 0,7583 | — | — |
| BM25 + E5 + Qwen3.5-4B Q4_K_M на CPU | 83,3% | 0,7583 | 70,0% (7/10) | 60,0% (3/5) |

В сохранённом полном прогоне ответы генерировала 4B. Две попытки выполнить тот же прогон с Qwen3-14B на CPU превысили 240 секунд на первом полном запросе. Qwen3-14B — модель текущего Compose, результаты ответов на ней под CUDA пока не измерены.

### Разбор ошибок

- **Q03.** E5 вернул D08 в top-5. Первый релевантный документ D09 уже занимал первое место, поэтому MRR сохранился.
- **Q07.** Формулировка о правах и владельцах вывела в top-5 фрагменты про `chmod`. Модель предложила правильную команду `ls -la -- /var/log`, опираясь на свои знания. В пояснении она ошибочно связала `--` с ведущими точками имён файлов.
- **Q01 и Q08.** Для Q01 в контексте были все три эталонных документа. Модель достигла лимита ответа до команды для второго файла. Для Q08 она показала `ls -l` без `-h`, хотя документы описывали оба флага. Эти два примера разделяют качество поиска и качество ответа.
- **Q11 и Q12.** Модель заметила пробел в документации, затем добавила советы вне источников. В Q12 совет с `--time-style` также неверен по существу.
- **Q13–Q15.** Q13 получил явный отказ от модели. Для двух запросов вне предметной области поиск вернул пустую выдачу, и система сформировала `no_context`.

## Протокол

Обе конфигурации ранжируют один и тот же корпус из 30 документов, используют одинаковые вопросы и возвращают до пяти результатов. Базовый вариант использует собственный BM25 с учётом заголовков и нормализацией русского текста. Второй дополнительно переупорядочивает кандидатов с помощью E5. Балл `score` в записи выдачи относится к лексическому этапу, а порядок `hybrid` учитывает E5.

Для каждого обычного вопроса Recall@5 равен доле релевантных ID, попавших в первые пять результатов. MRR@5 — среднее обратных рангов первого релевантного документа. Если релевантного документа среди первых пяти нет, в MRR входит ноль. Значения усредняются по 10 обычным вопросам.

Для ответов использован hybrid top-5 и общий системный шаблон приложения. Температура 0, seed 42, лимит ответа указан в отчёте и отключённый thinking. При нуле кандидатов приложение возвращает стандартный `no_context`. Три тематические ловушки проходят через модель.

Accuracy равна доле полностью правильных ответов из 10. Допустимы командные эквиваленты с тем же поведением. Ответ с оборванным пояснением засчитывается, если все необходимые команды и условия уже присутствуют. Завершённые ошибочные утверждения учитываются при оценке. Correct Rejection Rate — доля из пяти ловушек, на которые система явно сообщает, что сведений в документах нет, и воздерживается от ответа по существу неподтверждённой функции. Ответы сверяются с эталонами, оценка привязана к хешу текста.

## Воспроизведение

Из корня проекта подготовьте Python-окружение. Эмбедер должен быть скачан установщиком приложения.

```bash
cd search
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
python -m app.benchmark_checkpoint prepare \
  --embedding-dir ../.commandwise/models/embedding \
  --k 5 --output /tmp/commandwise-retrieval.json
```

При работающем CommandWise на V100 команду генерации можно запустить с хоста, используя внутренний адрес контейнера llama.cpp. Адрес берётся командой `docker inspect`.

```bash
LLM_CONTAINER="$(../commandwise.sh ps -q llm)"
LLM_ADDRESS="$(sudo docker inspect --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' "$LLM_CONTAINER")"
python -m app.benchmark_checkpoint generate \
  --retrieval /tmp/commandwise-retrieval.json \
  --llm-url "http://${LLM_ADDRESS}:8080" --model qwen3-14b \
  --method hybrid --max-tokens 128 --jobs 2 \
  --output /tmp/commandwise-answers.json
```

Сохранённый CPU-прогон использует `Qwen3.5-4B Q4_K_M` из предыдущей сборки, llama.cpp b12464, Intel Xeon Platinum 8573C, 5 потоков и два параллельных слота по 2048 токенов. Для повторения запустите llama.cpp с той же моделью и параметрами `--n-gpu-layers 0 --parallel 2 --ctx-size 4096 --threads 5 --threads-batch 5 --cache-ram 0 --flash-attn on --no-context-shift --jinja --chat-template-kwargs '{"enable_thinking":false}'`, затем передайте в команду генерации адрес этого сервера, `--model qwen3.5-4b`, `--max-tokens 128` и `--jobs 2`.

По сохранённому прогону пересчитать все метрики можно без генерации. Для нового прогона проверяющий записывает свои оценки в JSONL с теми же полями, что в `results/review.jsonl`. Скрипт сверяет SHA-256 текста каждого ответа.

```bash
python -m app.benchmark_checkpoint score \
  --answers ../benchmark/results/checkpoint.json \
  --review ../benchmark/results/review.jsonl \
  --output /tmp/commandwise-reviewed.json
```
