# CommandWise

Русскоязычный помощник по документации команд Linux. Пользователь выбирает систему, задаёт вопрос и получает ответ с фрагментами проверенной документации. В исходном корпусе подтверждена Debian 13. Новые варианты появляются в списке после публикации документов для них.

## Установка

Поддерживаются Debian 13 (Trixie) и Fedora Linux на x86_64. Понадобятся интернет, свободное место под Docker-образы и модели, установленный драйвер NVIDIA с поддержкой CUDA 12.8 и права root или sudo. Перед установкой проверьте, что `nvidia-smi -L` видит GPU. Для Tesla V100 подходит проприетарная ветка R580, последняя с поддержкой Volta. [Матрица совместимости NVIDIA](https://docs.nvidia.com/datacenter/tesla/drivers/latest/cuda-toolkit-driver-and-architecture-matrix.html)

### Debian 13

Распакуйте архив и из каталога проекта выполните:

```bash
./install-debian.sh
```

Установщик использует рабочий Docker и Compose, если они уже есть. При необходимости он установит пакеты из Debian или официального APT-репозитория Docker, затем настроит NVIDIA Container Toolkit. Установка сразу запускает сервисы. Для последующих запусков используйте:

```bash
./start-debian.sh
```

### Fedora

```bash
./install-fedora.sh
```

Руководство по установке драйвера для Fedora размещено на сайте RPM Fusion. [Руководство по NVIDIA](https://rpmfusion.org/Howto/NVIDIA)

Оба установщика скачивают модели, собирают сервисы и применяют миграции. При первой установке скрипт попросит логин и пароль администратора. Пароль вводится без отображения и хранится в PostgreSQL в виде bcrypt-хеша.

- [Пользовательский интерфейс](http://127.0.0.1:8080) предлагает зарегистрироваться или войти. Логин принимает 3–40 латинских букв, цифр, точек, дефисов или подчёркиваний. Пароль должен содержать от 8 символов, максимум 72 байта.
- [Панель администратора](http://127.0.0.1:8080/admin) открывается после входа с реквизитами установки. Пользовательский чат доступен аккаунтам, созданным через регистрацию.
- `./commandwise.sh ps` показывает состояние контейнеров. `./commandwise.sh logs -f backend search llm` показывает журналы.
- `./commandwise.sh stop` останавливает приложение. `./commandwise.sh up -d` запускает его снова. Повторный запуск установщика повторно использует скачанные веса, конфигурацию и тома.

Параметры адреса и порта лежат в `.commandwise/compose.env`. Для доступа через внешний HTTPS-прокси направьте его на `127.0.0.1:8080`, задайте полный HTTPS origin в `PUBLIC_ORIGIN`, установите `COOKIE_SECURE=true` и примените `./commandwise.sh up -d`. Прокси должен передавать исходный Host и пропускать поток SSE. Для нового локального порта измените `CW_PORT`. Тома `database` и `rag` содержат PostgreSQL и опубликованный корпус.

## Чаты и очередь

Можно создать до десяти чатов. Система и версия закрепляются за чатом. У пользователя одновременно выполняется один ответ, остальные чаты показывают «В очереди». Два аккаунта могут генерировать одновременно. В активном чате ответ появляется постепенно. Переключение вкладки чата и перезагрузка страницы сохраняют задания, а кнопка «Остановить» отменяет конкретное задание. Уже полученный текст остаётся в истории.

Номер под ответом открывает сохранённый фрагмент документации. Если подходящих фрагментов нет, чат сообщает об этом. Чат можно удалить после завершения или остановки задания.

## Добавление источника

Войдите в панель администратора, выберите файл `.md` в UTF-8 до 512 КиБ, укажите идентификатор документа, пакет и его версию, проверенные дистрибутив и релиз, ссылку и дату проверки. Разделы документа обозначаются заголовками `##` или `###`. Допускаются до 120 разделов по 4000 символов. Идентификатор должен отличаться от уже существующих.

````markdown
# systemctl

## Проверка состояния службы

Команда systemctl status показывает состояние выбранной службы.

```bash
systemctl status ssh.service
```
````

Панель подтверждает публикацию после успешного обновления поискового индекса и эмбеддингов. Уже сохранённые ответы продолжают ссылаться на те версии фрагментов, которые участвовали в генерации.

## Модель и поиск

- Локальная LLM — **Qwen3.5-4B Q4_K_M**. Файл модели занимает 2,74 ГБ. В Compose закреплён образ llama.cpp b12464 CUDA 12.8.1. Используются два слота по 8192 токена при общей настройке 16384 токена. Максимум ответа — 1024 токена, режим thinking отключён. [GGUF на Hugging Face](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/blob/main/Qwen3.5-4B-Q4_K_M.gguf)
- Эмбедер — **multilingual-e5-small** в формате ONNX на CPU. BM25 находит фрагменты для нужной версии системы, E5 уточняет порядок кандидатов. [Модель E5](https://huggingface.co/intfloat/multilingual-e5-small)
- Браузер получает JWT через HttpOnly-cookie. API-клиент может использовать `X-Auth-Mode: bearer` при входе и затем передавать `Authorization: Bearer <token>`. Методы и ответы описаны в [OpenAPI](spec/tech/api.yaml) и [спецификации SSE](spec/tech/api-behavior.md).

Журнал `./commandwise.sh logs llm` показывает размещение слоёв на GPU и размер контекста. Чтобы проверить два слота на своём хосте, откройте два независимых профиля браузера, зарегистрируйте два аккаунта и отправьте вопросы одновременно. В третьем чате любого из этих аккаунтов вопрос должен ждать. Во время проверки `nvidia-smi` показывает использование памяти GPU.

## Проверки разработки

```bash
cd backend
go fmt ./...
go vet ./...
go test ./...
COMMANDWISE_TEST_DSN='postgres://user:password@127.0.0.1/testdb?sslmode=disable' go test -race -v ./...
```

Интеграционный тест использует пустую тестовую PostgreSQL и управляемый сервис модели, чтобы воспроизводимо проверить параллельность и отмену. Для cron-запуска или CI реквизиты передаются только через переменные окружения.

```bash
cd frontend
npm ci
npm run typecheck
npm run build
```

```bash
cd search
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
python -m app.indexer --corpus ../corpus --output ../.local-index
COMMANDWISE_TEST_EMBEDDING_DIR=../.commandwise/models/embedding python -m pytest -q
```
