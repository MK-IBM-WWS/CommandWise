# CommandWise

Русскоязычный помощник по документации команд Linux. Пользователь выбирает Debian, Fedora или Arch Linux и получает ответ с фрагментами документации. Встроенный корпус содержит 50 команд. Каждый файл имеет три системных раздела с примерами и примечаниями. [Состав корпуса](corpus/README.md)

## Установка

Поддерживаются Debian 13 (Trixie) и Fedora Linux на x86_64. Понадобятся интернет, свободное место под Docker-образы и около 9,5 ГБ под модели, установленный драйвер NVIDIA с поддержкой CUDA 12.8 и права root или sudo. Перед установкой проверьте, что `nvidia-smi -L` видит GPU. Для Tesla V100 подходит проприетарная ветка R580, последняя с поддержкой Volta. [Матрица совместимости NVIDIA](https://docs.nvidia.com/datacenter/tesla/drivers/latest/cuda-toolkit-driver-and-architecture-matrix.html)

### Debian 13

Распакуйте архив и из каталога проекта выполните:

```bash
./install-debian.sh
```

Установщик использует рабочий Docker и Compose, если они уже есть. При необходимости он установит пакеты из Debian или официального APT-репозитория Docker, затем настроит NVIDIA Container Toolkit. Установка сразу запускает сервисы. Для последующих запусков используйте:

```bash
./start-debian.sh
```

### Fedora

```bash
./install-fedora.sh
```

Руководство по установке драйвера для Fedora размещено на сайте RPM Fusion. [Руководство по NVIDIA](https://rpmfusion.org/Howto/NVIDIA)

Оба установщика скачивают модели, собирают сервисы и применяют миграции. При первой установке скрипт попросит логин и пароль администратора. Пароль вводится без отображения и хранится в PostgreSQL в виде bcrypt-хеша.

- [Пользовательский интерфейс](http://127.0.0.1:8080) предлагает зарегистрироваться или войти. Логин принимает 3–40 латинских букв, цифр, точек, дефисов или подчёркиваний. Пароль должен содержать от 8 символов, максимум 72 байта.
- [Панель администратора](http://127.0.0.1:8080/admin) открывается после входа с реквизитами установки. Пользовательский чат доступен аккаунтам, созданным через регистрацию.
- `./commandwise.sh ps` показывает состояние контейнеров. `./commandwise.sh logs -f backend search llm` показывает журналы.
- `./commandwise.sh stop` останавливает приложение. `./commandwise.sh up -d` запускает его снова. Повторный запуск установщика повторно использует скачанные веса, конфигурацию и тома.

Параметры адреса и порта лежат в `.commandwise/compose.env`. Для доступа через внешний HTTPS-прокси направьте его на `127.0.0.1:8080`, задайте полный HTTPS origin в `PUBLIC_ORIGIN`, установите `COOKIE_SECURE=true` и примените `./commandwise.sh up -d`. Прокси должен передавать исходный Host и пропускать поток SSE. Для нового локального порта измените `CW_PORT`. Тома `database` и `rag` содержат PostgreSQL и опубликованный корпус.

## Ошибка подключения PostgreSQL

Сообщение `password authentication failed for user "commandwise"` относится к паролю PostgreSQL из `.commandwise/compose.env`. Такое бывает, если существующий том базы был создан с другим паролем. При переустановке применяй обновление из каталога проекта с сохранённой папкой `.commandwise`.

Установщик и скрипт запуска проверяют сетевой вход в базу. При штатных настройках PostgreSQL они могут синхронизировать служебный пароль через локальный сокет. Запустить проверку и восстановление отдельно можно так:

```bash
./repair-db-auth.sh
```

Восстановление сохраняет том, чаты и аккаунты. Если локальная политика PostgreSQL запрещает вход через сокет, администратор этой базы должен сверить пароль роли `commandwise` с `.commandwise/compose.env` через свой штатный административный доступ.

## Контейнер Search в состоянии unhealthy

При таком сбое Compose удерживает запуск backend до готовности индекса. Скрипт запуска выводит состояние контейнеров и журнал Search. Отдельно журнал можно открыть командой:

```bash
./commandwise.sh logs --tail=100 search
```

Обновите исходники в каталоге уже установленного приложения, сохранив `.commandwise`. Пересоберите Search и запустите приложение:

```bash
./commandwise.sh build search && ./start-debian.sh
```

На Fedora вместо `./start-debian.sh` выполните `bash infra/start.sh`. При повреждении индекса или векторов Search пересчитывает их из сохранённых Markdown-документов. Первый запуск и пересборку можно отслеживать через `./commandwise.sh logs -f search`.

При обновлении поверх старой версии в `corpus/docs` могут остаться Markdown-файлы. Search берёт встроенные документы из списка в `corpus/manifest.json` и записывает имена пропущенных файлов в журнал. Если файл из списка отсутствует, восстановите его из архива той же версии и пересоберите Search.

## Удаление

```bash
./uninstall.sh
```

Команда удаляет контейнеры и сеть. Аккаунты, чаты, опубликованные документы, модели и настройки сохраняются для повторного запуска.

```bash
./uninstall.sh --purge
```

Этот вариант также удаляет тома с аккаунтами, чатами и корпусом, локальные образы сборки и каталог `.commandwise` с настройками и моделями. Исходники, Docker и системные пакеты остаются на сервере.

## Чаты и очередь

Можно создать до десяти чатов. Дистрибутив закрепляется за чатом. У пользователя одновременно выполняется один ответ, остальные чаты показывают «В очереди». Два аккаунта могут генерировать одновременно. В активном чате ответ появляется постепенно. Переключение вкладки чата и перезагрузка страницы сохраняют задания, а кнопка «Остановить» отменяет конкретное задание. Уже полученный текст остаётся в истории.

Номер под ответом открывает сохранённый фрагмент документации. Если подходящих фрагментов нет, чат сообщает об этом. Чат можно удалить после завершения или остановки задания.

## Добавление источника

Войдите в панель администратора, выберите файл `.md` в UTF-8 до 512 КиБ, укажите идентификатор документа, пакет и его версию, дистрибутив, ссылку и дату проверки. Разделы документа обозначаются заголовками `##` или `###`. Допускаются до 120 разделов по 4000 символов. Идентификатор должен отличаться от уже существующих.

````markdown
# systemctl

## Проверка состояния службы

Команда systemctl status показывает состояние выбранной службы.

```bash
systemctl status ssh.service
```
````

Панель подтверждает публикацию после успешного обновления поискового индекса и эмбеддингов. Уже сохранённые ответы продолжают ссылаться на те версии фрагментов, которые участвовали в генерации.

## Модель и поиск

- Локальная LLM — **Qwen3-14B Q4_K_M** из репозитория Qwen. Файл весов занимает 9,00 ГБ (около 8,38 ГиБ). Compose использует llama.cpp b12464 CUDA 12.8.1, два слота по 4096 токенов и до 1024 токенов на ответ. Thinking отключён. Для V100 16 ГБ расчётный FP16 KV-кэш для двух слотов составляет около 1,25 ГиБ, поверх весов и рабочих буферов CUDA. Фактическое потребление VRAM под нагрузкой измеряется на сервере. [GGUF на Hugging Face](https://huggingface.co/Qwen/Qwen3-14B-GGUF/blob/530227a7d994db8eca5ab5ced2fb692b614357fd/Qwen3-14B-Q4_K_M.gguf)
- Эмбедер — **multilingual-e5-small** в формате ONNX на CPU. Собственный BM25 использует инвертированный индекс, E5 уточняет порядок кандидатов для выбранной системы. [Модель E5](https://huggingface.co/intfloat/multilingual-e5-small)
- Браузер получает JWT через HttpOnly-cookie. API-клиент может использовать `X-Auth-Mode: bearer` при входе и затем передавать `Authorization: Bearer <token>`. Методы и ответы описаны в [OpenAPI](spec/tech/api.yaml) и [спецификации SSE](spec/tech/api-behavior.md).

Журнал `./commandwise.sh logs llm` показывает размещение слоёв на GPU и размер контекста. Чтобы проверить два слота на своём хосте, откройте два независимых профиля браузера, зарегистрируйте два аккаунта и отправьте вопросы одновременно. В третьем чате любого из этих аккаунтов вопрос должен ждать. Во время проверки `nvidia-smi` показывает использование памяти GPU.

## Benchmark контрольной точки

В каталоге `benchmark/` лежат 30 зафиксированных фрагментов Debian 13, 10 обычных вопросов с тремя или четырьмя релевантными ID и эталонами, а также 5 ловушек. Сохранены выдача обеих конфигураций поиска, ответы контрольного CPU-прогона Qwen3.5-4B, оценка каждого ответа и четыре метрики. [Воспроизведение и разбор ошибок](benchmark/README.md)

При обновлении поверх установленной версии запусти установщик своей ОС. При старте поисковый сервис один раз объединит обновлённые встроенные документы с ранее загруженными через админку и пересчитает индекс. В журналах `./commandwise.sh logs -f search` можно следить за готовностью. Веса 14B скачиваются в отдельный файл `.commandwise/models/llm/qwen3-14b.gguf`. Тома Compose содержат аккаунты, чаты и опубликованный корпус.

## Проверки разработки

```bash
cd backend
go fmt ./...
go vet ./...
go test ./...
COMMANDWISE_TEST_DSN='postgres://user:password@127.0.0.1/testdb?sslmode=disable' go test -race -v ./...
```

Интеграционный тест использует пустую тестовую PostgreSQL и управляемый сервис модели, чтобы воспроизводимо проверить параллельность и отмену. Для cron-запуска или CI реквизиты передаются только через переменные окружения.

```bash
cd frontend
npm ci
npm run typecheck
npm run build
```

```bash
cd search
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
python -m app.indexer --corpus ../corpus --output ../.local-index
COMMANDWISE_TEST_EMBEDDING_DIR=../.commandwise/models/embedding python -m pytest -q
```

Результаты проверок этой сборки приведены в [истории изменений](CHANGE_HISTORY.md).
